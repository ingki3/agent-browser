# 알려진 한계

[← 문서 목차](README.md)

**모델 판단의 편차** — 실패 사례는 런타임 결함이 아니라 LLM이 실행마다 다른 선택을 하는 경우입니다. `max_tokens` 조정으로 해결되지 않으며, 모델 비교가 다음 과제입니다.

**액션 뒤 이동 대기는 문서 요청만 봅니다** — SPA의 `pushState` 라우팅(문서 요청 없음)과, 액션 뒤 200ms가 지나서 시작되는 이동(예: 400ms 뒤 JS로 `location` 변경)은 이동 대기(200ms 감지 창)가 기다리지 않습니다. 단 효과가 전혀 없던 `click` 은 늦은 효과 창(3초, WS-97)이 그 이동을 다시 봅니다 — 그 창 안 문서 요청은 남은 창 시간만 기다리고 정상 문서로 커밋된 이동(오류 문서·같은 주소 재요청 제외)만 효과입니다(글자만 바뀐 렌더링은 효과가 아님). 그 밖의 액션(`press_key`·`select_option` 등)과 3초를 넘긴 효과는 기존 사후조건 검증과 루프의 관찰 재시도가 맡습니다(click 은 '3초 동안 확인 가능한 효과가 보이지 않음' 문구의 `E_TIMEOUT` — 다시 누르기 전에 관찰로 확인). 연결 실패가 Chromium 오류 문서(`chrome-error://`)로 커밋되면 새 문서로 보아 `nav_committed=true`로 남습니다.

**늦은 효과 창의 한계(WS-97 #280)** — 창은 효과가 전혀 없는 element_id·selector `click` 에만 있고(좌표·SoM 클릭은 기존처럼 유예·창 없음), 근거는 ① 정상 문서 커밋 ② 이 클릭이 연 새 탭(popup·`Page.windowOpen`) ③ 대상 노드의 `aria-expanded`·`aria-pressed`·`checked`·`value` ④ `pushState`(history.length 증가) 뿐입니다([signals.md](signals.md)). 그래서 **글자만 바뀌는 늦은 효과는 확인 안 됨** — 1~3초 뒤 결과 글자만 렌더하는 조회, 늦은 "완료" alert(다이얼로그), class 만 바뀌는 버튼, `replaceState`·해시로만 주소를 바꾸는 화면, 같은 주소로 다시 제출하는 폼은 실제로 효과가 있었어도 `E_TIMEOUT`(새 문구)입니다(거짓 성공보다 거짓 실패 쪽). 3초를 넘긴 효과도 같습니다. 남은 위험(거짓 성공): 액션 밖 popup 이력이 아직 없는 탭에서 **첫 자발 popup**(광고 타이머)이 마침 창 안에 오면 이 클릭의 새 탭으로 셉니다(기존 150ms 유예와 같은 계열, 창이 길어 확률이 커짐 — 그 뒤로 그 탭의 창 안 popup 은 근거가 아님). 대상 탭이 **타이머로 스스로 이동**(세션 만료 리다이렉트·JS `location` 이동)하는 것이 창 안에 오면 문서 커밋 근거로 성공합니다 — 같은 주소 재요청·`reload` 형만 뺍니다(메타 refresh 가 다른 주소로 가는 경우는 구별하지 못함). 페이지가 대상 노드의 `aria-expanded`·`value` 를 자발로 바꾸는 경우도 같습니다. 창 진입 전 즉시 판정에는 이 규칙이 없어, 클릭 직후 스냅샷에 든 빠른 자발 변화(250ms 광고 로테이션)는 지금처럼 거짓 성공일 수 있습니다(#294). 무반응 클릭은 약 3초 느려지고(그동안 같은 작업 공간의 다음 호출도 밀림), 탭마다 첫 click 앞에 한 번 `Page.windowOpen` 감시 세션을 엽니다.

**브라우저 언어(WS-97 #293)** — 기본 `ko-KR` 이어도 `validationMessage`("Please fill out this field.") 같은 브라우저 고유 문구는 영어로 남습니다(Chromium UI 언어는 locale 과 별개). locale 은 프로필에 저장되지 않습니다 — 사이트가 쿠키·저장소에 남긴 언어 설정(예: '설정된 언어: English')이 있으면 그 사이트는 여전히 영어판일 수 있습니다. 영어판에서 기록된 레시피 이름(예: `Book`)은 한국어판 재생에서 `target_not_found` 로 멈춥니다(fail-closed).

**클릭 목적 신호는 페이지 자기 서술을 믿습니다** — `target_selected`(WS-90)는 클릭한 노드 자신의 `aria-selected="true"` 를 봅니다. 페이지가 클릭한 탭에 거짓으로 `aria-selected="true"` 를 두면(화면에는 다른 탭이 선택) 무효 클릭도 성공입니다. 선택 상태를 클래스로만 표시하는 탭은 이 신호를 받지 못해 기존처럼 `E_TIMEOUT` 입니다.

**Tier-2 시각 폴백은 옵트인입니다** — 텍스트 셀렉터가 2회 연속 실패하면(아이콘 버튼, 난독화 라벨, Canvas UI) 스크린샷에 태그를 얹어 비전 모델에게 묻는 폴백이 있습니다. `serve --som-vision`으로 켭니다. 끄면 `take_screenshot(annotate_som=True)`는 이전처럼 `E_FEATURE_NOT_IMPLEMENTED`를 반환합니다(레거시 클라이언트 보호).

```bash
agent-browser serve --som-vision          # Tier-2 활성화
OPENROUTER_VISION_MODEL=...               # 선택. 없으면 OPENROUTER_MODEL 사용
```

- 발동은 무인 모드 태스크당 3회로 제한되며, 캡처 1장당 1,600토큰이 예산에 합산됩니다.
- 순수 Canvas는 DOM 대상이 없으므로 좌표 클릭(`click(x, y, epoch)`)으로 처리합니다. 좌표 모드는 클릭만 지원합니다.
- 이미지 안의 텍스트는 신뢰하지 않는다는 비전 프롬프트 래퍼가 강제됩니다.
- 비전 모델 지연은 기준(p95 ≤ 3.5초)에 맞는 모델을 골라야 합니다. `python -m harness.tier2_som --vlm live`로 실측합니다. **다만 실측한 비전 모델 8종 중 이 기준을 만족한 모델은 없었습니다**(p50은 2.7~3.1초대이나 max가 12~25초로 튐). 현재는 `OPENROUTER_MODEL`(glm-5.3-flash)을 그대로 사용합니다.
- **아이콘만으로 판별해야 하는 화면은 기권할 수 있습니다** — 라벨이 난수이고 SVG 아이콘 그림이 유일한 단서인 경우, 실측상 8회 중 2회 "해당 요소 없음"을 반환했습니다. 오답 클릭이 아니라 클릭하지 않는 쪽(fail-closed)이며, 이때 태스크는 실패로 끝납니다.
- **비전 모델은 좌표계를 일관되게 지키지 않습니다** — 절대 픽셀 대신 0~1000 정규화 좌표를 섞어 반환하는 사례를 gemini·glm 양쪽에서 관측했습니다. 응답에 `coord_space`(`absolute` / `normalized_1000`) 선언을 요구해 변환하며, 선언이 없으면 절대 픽셀로, 모르는 값이면 좌표를 버립니다(추측하지 않음). 단 모델이 정규화 좌표를 내면서 `absolute`로 잘못 선언하는 경우가 있어 이 처리로 전부 걸러지지는 않습니다.

**레시피(동작 캐시)의 한계** — 같은 일을 반복할 때만 이득이 있습니다. 화면 밖에 항목이 없는 무한 스크롤·가상 목록은 순번이 화면 기준이 됩니다(범위를 넘으면 멈춤). 골격 서명은 구조가 조금만 달라도(목록 개수는 접어도 형제 구성이 바뀌면) 헛경보로 멈출 수 있습니다 — 안전하지만 재생 기회를 놓칩니다. 외부 링크로 가득한 목록(뉴스 제목 등)은 href 패턴이 '외부'로만 비교돼 틀 확인이 약하고, 광고 자리는 slot 으로도 같은 광고 틀의 다른 링크를 고를 수 있습니다(M-1 재측정 1건). 틀까지 흉내 낸 페이지 조작은 일반 클릭과 같은 위험 수준입니다. 프레임 안·shadow DOM 대상은 기록하지 않습니다.

소셜 로그인 자동화를 지원하지 않는 이유와 대신 쓰는 세션 저장 방식, 자격증명 다루기는 [security.md](security.md#로그인-세션과-자격증명)에 있습니다.
